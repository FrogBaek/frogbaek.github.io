컴퓨터의 구조와 동작 원리

2024년 12월 3일 · 14 min

들어가며#

자료구조와 알고리즘을 본격적으로 공부하기에 앞서, 컴퓨터의 전반적인 역사와 하드웨어의 종류 및 역할, 그리고 컴퓨터의 구조와 동작 원리에 대해 정리하였습니다.

이 글은 백엔드 분야를 공부하고 있는 비전공자의 글이며, 잘못된 내용에 대한 지적은 언제나 환영합니다. inflearn의 홍정모 강사님의 따배씨 강의를 참고하였으며, 다른 서적과 구글링을 통해 보충한 내용을 정리한 공부 목적의 글입니다.


1. 배우기 앞서#

본격적인 공부에 앞서, 컴퓨터의 구성 요소부터 간단하게 알아보겠습니다. 참고 자료: 위키백과

위 그림은 사용자가 사용하고 있는 컴퓨터의 본체와 입출력 장치들을 간단하게 도식화한 것입니다. (현대에서는 입력장치와 출력장치 또한 다른 컴퓨터가 그 기능을 수행할 수 있지만, 지금은 간단하게 알아보기 위해 제외하였습니다.)

사용자가 이 글을 쓰기 위해서 컴퓨터 본체의 전원공급장치와 연결된 전원 버튼을 눌러 출력장치인 모니터를 켜고, 입력장치인 마우스를 통해 블로그에 접속한 뒤, 키보드라는 입력장치를 사용하여 글을 작성하고 있는 것입니다. 컴퓨터 본체의 구성 요소는 아래와 같습니다.

  • 중앙처리장치(CPU, Central Processing Unit): 컴퓨터의 두뇌 역할을 하며, 실질적으로 모든 연산을 수행하는 핵심 요소입니다. Intel과 AMD가 대표적인 제조사입니다.
  • 주 기억장치(Primary Storage): CPU와 함께 동작하는 저장 공간을 담당하는 요소이며, 흔히 RAM이라고 불리는 메모리가 이에 해당합니다.
  • 그래픽스 카드(Graphics Card): 그래픽 작업을 전문적으로 처리하는 요소입니다. NVIDIA의 Geforce 시리즈 등이 대표적입니다.
  • 보조 기억장치(Secondary Storage): Windows, macOS, Linux와 같은 운영체제를 저장하고, 사용자가 원하는 프로그램 등을 저장하는 공간입니다. HDD, SSD 등이 이에 해당합니다.
  • 전원공급장치(Power Supply): 구동에 필요한 전력을 컴퓨터에 공급해주는 장치입니다. 최근 그래픽스 카드 등 구성 요소의 성능이 높아짐에 따라, 전원공급장치의 용량도 함께 고려해야 하는 중요한 요소가 되었습니다.
  • 메인보드(Main Board): 컴퓨터 본체 내부에 위치한 주회로가 내장된 보드입니다. 부팅을 도와주는 BIOS라는 프로그램을 실행할 자체 CPU를 가지고 있습니다.

여담으로, 예전에는 FDD(Floppy Disk Drive)라는 보조 기억 장치를 사용했는데, 이를 구분하기 위한 용도로 A와 B 드라이브 문자를 사용했습니다. 그래서 시간이 흘러 현재 우리가 사용하는 로컬 디스크의 이름이 C, D부터 시작하게 된 것입니다.


이제 위 설명을 바탕으로 구성 요소들의 역할을 컴퓨터의 부팅 절차를 통해 조금 더 자세히 알아보겠습니다. 참고 자료: 기억장치의 계층구조

  1. 사용자가 글을 쓰기 위해 컴퓨터의 전원을 켜면, 전원공급장치를 통해 메인보드에 전력이 공급됩니다.
  2. 메인보드에 장착된 CPU가 ROM(Read Only Memory)에 저장되어 있는 BIOS(Basic Input Output System)를 실행합니다.
  3. BIOS로 주변 하드웨어 장치들을 검사하는 POST(Power On Self Test) 과정을 거치고, 부팅할 보조 기억장치를 선택하여 내장된 부트로더(Boot Loader)를 실행합니다.
  4. 부트로더가 Windows라는 OS(Operating System)를 RAM(Random Access Memory)에 적재합니다. (OS Loading)
  5. RAM을 기반으로 CPU가 본격적으로 사용자의 명령을 처리하게 됩니다.

위 과정은 상세한 부팅 절차를 매우 간략하게 축소한 것입니다. 여기서 알아야 할 중요한 특징이 있습니다.

CPU가 보조 기억장치에 직접 접근하지 않는 이유#

CPU는 보조 기억장치(HDD, SSD 등)에 직접 접근하지 않고, 주 기억장치(RAM, ROM 등)와 함께 동작합니다. 그 이유는 위 그림과 같이 기억 장치의 용량, 속도, 비용 간의 관계 때문입니다.

속도가 느리고 용량이 큰 보조 기억장치의 내용 중에서, CPU가 자주 사용하는 데이터를 속도가 빠른 주 기억장치로 옮겨 놓고 사용함으로써, 전체적인 기억장치 액세스 속도를 개선하기 위한 것입니다. (캐시와 레지스터에 대해서는 뒤에서 더 자세히 다루겠습니다.)

주 기억장치: ROM과 RAM#

주 기억장치는 ROM(Read Only Memory)과 RAM(Random Access Memory)으로 구성되어 있습니다.

ROM은 내용을 읽을 수는 있어도 바꿀 수는 없는 기억장치이며, 컴퓨터의 전원이 꺼져도 내용이 유지됩니다. 주로 BIOS와 같이 한 번 설정해놓고 변경하지 않아도 되는 프로그램이 저장되어 있습니다.

RAM은 컴퓨터의 전원이 꺼지면 저장된 데이터가 모두 삭제되는 휘발성 기억장치이며, 보조 기억장치보다 용량은 적지만 속도는 훨씬 빠릅니다. 이름에서 알 수 있듯이 임의 접근(Random Access) 방식의 기억장치입니다.

순차 접근과 임의 접근#

순차 접근(Sequential Access): 위 그림과 같이 일렬로 저장된 데이터를 차례대로 액세스하는 방식입니다. 필요한 데이터가 저장된 위치에 따라 액세스 시간이 달라집니다. 자기 테이프(Magnetic Tape)로 정보를 저장하던 시절에 주로 사용되었습니다.

임의 접근(Random Access): 주소를 통해 데이터에 직접 액세스하는 방식입니다. 어떤 데이터를 기억 장소에 기록하거나 읽어낼 때, 기억 장소의 위치에 관계없이 동일한 시간이 소요됩니다. 각 기억장치의 위치마다 고유의 주소가 할당되어 있으며, C 언어에서 배우는 포인터라는 개념이 바로 이 주소 체계에서 비롯된 것입니다.

운영체제(Operating System)#

운영체제(Operating System)는 사용자(또는 소프트웨어 엔지니어)가 컴퓨터 하드웨어를 쉽게 사용할 수 있도록 인터페이스를 제공해주는 소프트웨어입니다. 운영체제 덕분에 현대의 프로그래머들은 하드웨어를 직접 조작하는 프로그램을 별도로 작성할 필요가 없어졌습니다. 운영체제가 없었다면, 프로그램을 만들 때마다 하드웨어를 제어하는 코드를 전부 직접 작성해야 했을 것입니다. (실제로 초기에는 Plug Board나 Punched Card에 물리적 작업을 통해 프로그래밍을 했습니다.)

대표적인 운영체제로는 UNIX, Linux, Windows, macOS, Android, iOS 등이 있습니다.

위 그림을 예로 들면, 사용자가 게임을 실행할 때 Windows라는 운영체제가 마우스, 키보드, 스피커 같은 입출력장치와 게임이라는 응용 프로그램을 커널이라는 운영체제의 핵심 요소를 통해 원활하게 연결시켜 줍니다.

또한 게임을 하면서 동시에 YouTube를 재생하고 KakaoTalk을 사용할 수 있는 것도 운영체제 덕분입니다. 이때 각 응용 프로그램이 CPU나 메모리 같은 하드웨어의 자원(Resource)을 누가 먼저, 얼마나 사용할지를 효율적으로 관리해주는 역할 또한 운영체제가 수행합니다.


2. 컴퓨터의 역사#

현재 우리는 일상생활에서 10을 기수로 하는 십진법을 사용하고 있습니다. 사람의 손가락이 10개이기 때문에 자연스럽게 정착된 것입니다. 하지만 컴퓨터는 10진수가 아닌 2진수를 사용합니다. 왜 컴퓨터는 이진법을 채택하게 되었을까요?

참고 자료: Samsung Semiconductor Newsroom, 위키백과

그 시작은 세계 최초 컴퓨터인 ENIAC 개발의 토대가 된 진공관 덕분입니다. 이를 이해하려면 먼저 에디슨 효과에 대해 알아야 합니다.

에디슨 효과(리처드슨 효과, 열전자방출): 1883년 토마스 에디슨(Thomas Edison)이 백열전구 내부에 검은 그을음이 생기는 것에 대해 실험하던 중, 전류가 필라멘트와 양전하로 입혀진 금속판 사이의 진공 속으로 흐른다는 것을 발견한 현상을 의미합니다.

이 에디슨 효과를 1904년 영국의 전기공학자인 존 엠브로즈 플레밍(John Ambrose Fleming)이 연구하고 응용하여 진공관을 발명하게 됩니다.

진공관: 진공 속에서 전자의 움직임을 제어함으로써 전기 신호를 증폭시키거나 교류를 직류로 정류하는 데 사용하는 전기 장비입니다. 현대에서도 높은 주파수와 큰 전력을 사용하는 장비 또는 오디오 앰프 등에 일부 사용되고 있습니다.

진공관은 상측의 플레이트(양극)와 하측의 캐소드(음극)의 한 쌍으로 이루어져 있습니다. 캐소드 아래에는 히터(필라멘트)라는 전열선이 있습니다.

히터에 전압을 걸어 전류를 흘리면 음극판이 가열되어 자유 전자들이 활발하게 움직이게 됩니다. 이때 양극에 플러스 전압을 가하면, 음극 내의 전자가 양극의 플러스 전위에 이끌려 진공을 통해 양극으로 이동하면서 전류가 흐르게 됩니다. 반대로 양극의 전위를 마이너스로 하면, 전자가 양극에 반발하여 방출되지 못하므로 전류는 흐르지 않습니다.

  • 전류가 흐른다 = 켜짐(1)
  • 전류가 흐르지 않는다 = 꺼짐(0)

컴퓨터는 이처럼 단순히 “전류가 흐른다(1)“와 “흐르지 않는다(0)“를 구분하는 것에서 시작되었습니다. 이 두 가지 상태를 조합하여 산술/논리 연산을 수행하게 되었고, 더 나아가 인간의 언어를 컴퓨터의 언어로 변환(Compile)해주는 것까지 가능해진 것입니다.

진공관의 발명 이후, 1946년 ENIAC이라는 세계 최초의 컴퓨터가 발명되었습니다. 하지만 부피가 너무 컸을 뿐만 아니라, 사용 시 항상 고온 상태였던 진공관의 특성 때문에 열에 의한 고장의 위험이 컸습니다. 이를 보완하기 위해 등장한 것이 바로 트랜지스터입니다.

트랜지스터: 1948년 미국 벨 연구소에서 근무하던 쇼클리, 바딘, 브래튼이 발명한 전자 부품입니다. 트랜지스터 덕분에 작은 전기 신호로도 큰 전기 신호를 제어할 수 있게 되었고, 이를 기점으로 정보 기술이 급격히 발전하게 되었습니다. 현재 우리가 사용하는 CPU 내부에는 이러한 트랜지스터가 수십억 개 이상 집적되어 있습니다.


이러한 과정을 거친 현대 컴퓨터의 기본 구조는 어떻게 이루어져 있을까요? 참고 자료: 위키백과, WIKIPEDIA

초기에는 프로그래머가 직접 Plug Board(위 그림)의 전기 배선을 바꾸거나 Punched Card(아래 그림)의 적절한 위치에 구멍을 뚫어가며 프로그래밍을 해야 했습니다.

하지만 이후 폰 노이만 구조의 등장으로 프로그래밍 방식은 근본적으로 달라지게 되었습니다.

폰 노이만 구조(Stored-program Computer): 1945년 수학자이자 물리학자인 존 폰 노이만 등이 서술한 컴퓨터 아키텍처입니다.

내장 메모리 순차 처리 방식으로서, 데이터 메모리와 프로그램 메모리가 구분되어 있지 않고 하나의 버스(Bus)를 가지고 있는 구조를 말합니다. 프로그램이 컴퓨터 외부가 아닌 내부 메모리에 저장되게 된 것입니다. 이후 폰 노이만 구조가 발전하여 현대 컴퓨터는 다음과 같은 구조를 갖게 되었습니다.

이로 인해 CPU와 Memory는 직접 연결되는 것이 아니라, System Bus를 통해 통신하게 됩니다. System Bus는 컴퓨터의 구성 요소를 서로 연결하고 데이터 전달을 위한 경로이며, Control Bus, Address Bus, Data Bus로 구성되어 있습니다.


3. CPU와 Memory#

지금까지 알아본 내용은 CPU와 Memory를 이해하기 위한 준비 과정이었습니다. 프로그래머로서 반드시 알아야 할 CPU와 Memory의 구조 및 동작 원리를 알아보겠습니다.

참고 자료: CPU와 메모리 이미지, DRAM 저장 유닛 구조도

CPU와 Memory는 함께 동작합니다. 연산은 CPU에서, 정보 저장은 Memory에서 담당합니다.

캐시 메모리#

Memory에서 CPU로 정보를 보낼 때, 동일한 데이터를 매번 새롭게 전송한다면 그 자체로 성능이 저하됩니다. 캐시 메모리는 자주 사용되는 데이터를 별도로 저장해두었다가, CPU가 같은 작업을 처리할 때 메모리 대신 캐시에서 데이터를 전달함으로써 연산 속도를 향상시키는 역할을 합니다.

RAM의 접근 방식#

현재 Memory를 이야기할 때 흔히 RAM(Random Access Memory)을 지칭합니다. 여기서 주목할 것은 임의 접근(Random Access)입니다.

시스템이 파일에 접근하는 방식은 크게 순차 접근(Sequential Access)과 임의 접근(Random Access), 직접 접근(Direct Access)으로 나뉩니다. 다음 예시를 통해 이해할 수 있습니다.

  • 순차 접근: 집에서 리모컨을 찾고 싶은데, 어디에 있는지 모르기 때문에 현관과 가까운 방부터 먼 방까지 순서대로 모두 뒤져보는 것
  • 임의 접근: 가족 구성원이 “주방 식탁 아래에 있다"고 알려줘서, 다른 방을 뒤져보지 않고 바로 주방에서 찾아내는 것

이를 통해 임의 접근이 효율적인 방식임을 알 수 있습니다.

메모리의 구조#

여기서 알아볼 것은 트랜지스터(Transistor)와 커패시터(Capacitor)로 하나의 Cell(셀)이 구성되고, 이 Cell은 0 또는 1의 값을 가지는 하나의 비트(Binary digit)를 저장한다는 점입니다. 비트는 메모리의 가장 작은 단위입니다.

커패시터를 나타내는 삼각형 부분은 그라운드(Ground)로, 흐르던 전류를 소멸시키는 역할을 합니다.

CPU와 RAM의 통신#

앞서 설명한 임의 접근을 위해, 현대의 메인보드는 위 그림과 같이 주소가 오가는 통로와 데이터가 오가는 통로가 분리되어 있도록 설계되어 있습니다. RAM이 장착되어 있다는 가정하에 그 과정을 살펴보겠습니다.

더 자세한 내용은 How a CPU Works (YouTube)를 참고하시기 바랍니다.

  1. Address Bus를 통해 원하는 주소에 접근합니다.
  2. Control Bus를 통해 데이터를 RAM으로부터 받을 것인지, RAM에 보낼 것인지를 제어합니다.
  3. Data Bus를 통해 데이터를 주고받습니다.

이를 통해 RAM의 기능은 두 가지임을 알 수 있습니다.

  1. CPU에게 데이터를 보내주는 것
  2. CPU로부터 데이터를 받아서 저장하는 것

추가로, Address Bus 때문에 포인터라는 개념이 존재합니다. C 언어와 같은 언어에서는 포인터를 직접 다루지만, Java 같은 언어에서는 포인터가 보이지 않습니다. 그렇다고 포인터가 존재하지 않는 것이 아니라, 프로그래머가 Data Bus를 통해 주고받는 데이터에만 집중할 수 있도록 언어 차원에서 감추어 놓은 것입니다.


프로그램이 시작되는 과정을 알아보고, CPU의 기본 구조와 구성 요소를 살펴보겠습니다.

참고 자료: 위키백과, CPU 명령어 구성

프로그램의 실행 과정#

  1. 프로그램은 보조 기억장치에 먼저 저장됩니다.
  2. 프로그램을 실행시키기 위해 내부적으로 운영체제에 요청하여, CPU가 아닌 주 기억장치(RAM)로 복사합니다. (보조 기억장치가 CPU와 직접 동작하지 않는 이유)
  3. 그제서야 CPU가 주 기억장치와 통신하며 프로그램을 실행하게 됩니다.

앞서 설명한 운영체제의 실행 과정과 동일한 흐름입니다.

CPU의 언어#

  • 기계어(Machine Code): CPU가 직접 해독하고 실행할 수 있는 비트 단위의 컴퓨터 언어로, 컴퓨터가 이해할 수 있는 유일한 언어입니다. (예: 1001, 01011100)
  • 어셈블리 언어(Assembly Language): 기계어와 일대일 대응이 되는 저급 언어로, 컴퓨터 프로세서를 다루기 위한 가장 기본적인 언어입니다. 기계어를 인간이 인식할 수 있는 기호로 바꾸어주는 니모닉(mnemonic) 과정을 거칩니다. (예: LOAD X, ADD Y, STORE Z)
  • 고수준 프로그래밍 언어(High-level Programming Language): 사람이 이해하기 쉽게 작성된 프로그래밍 언어로, 저급 언어보다 가독성이 높고 다루기 간단합니다. (예: A = 1, B = 2, C = A + B)

CPU의 구성 요소#

  • 제어 장치(Control Unit): 프로세서의 동작을 지시하는 역할을 합니다.
  • 산술 논리 장치(ALU, Arithmetic Logic Unit): 연산 작업과 논리 판단을 수행합니다.
  • 레지스터(Register): CPU가 요청을 처리하는 데 필요한 데이터를 일시적으로 저장하는 기억장치입니다.

레지스터의 구성 요소는 다음과 같습니다.

레지스터역할
주소 레지스터Address Bus에 주소를 출력하기 전에 임시 저장
프로그램 카운터다음에 인출할 명령어 주소를 임시 저장
데이터 레지스터Data Bus를 통해 데이터를 읽고 쓰기 위한 버퍼
명령어 레지스터가장 최근에 인출된 명령어를 임시 저장
어큐뮬레이터ALU의 중간 연산 결과를 임시 저장

여기서 의문이 생길 수 있습니다. “레지스터도 저장 공간이면 메모리와 같은 것 아닌가?”

결론부터 말하면, 저장 공간이라는 기능적 측면에서는 유사하지만, 레지스터와 메모리는 같지 않습니다. CPU가 메모리에 접근할 때는 Bus를 통해야 하므로 이동 시간이 별도로 발생합니다. 이는 연산 속도를 늦추어 성능 저하를 초래하므로, 이동할 필요가 없는 CPU 전용 저장 공간을 만들어 CPU 가까이에 두게 된 것입니다. 그것이 바로 레지스터입니다.

CPU가 수행하는 기본 명령은 많지 않습니다. 하지만 숫자를 더하고, 비교하고, 저장하고, 가져오는 등의 기본 작업을 조합하여 복잡한 기능을 수행할 수 있습니다.

논리 게이트#

CPU는 수많은 트랜지스터의 조합으로 이루어져 있습니다. ALU가 트랜지스터로 논리 연산을 어떻게 수행하는지, 기본적인 논리 게이트(Logic Gate)를 통해 알아보겠습니다.

진공관의 원리를 알면 이해가 수월합니다. 기억이 나지 않는 분은 위의 진공관 설명을 참고하시기 바랍니다. 편의상 거짓(0), 참(1)이라는 표현을 사용합니다.

1. NOT Gate (입력의 반대를 출력하는 부품)

전류가 흐르는 전선 위에 트랜지스터를 배치합니다. 트랜지스터에 0을 넣으면(전류를 차단하면) 1이 출력되고, 1을 넣으면(전류를 흘려보내면) 전류가 트랜지스터를 통과하여 그라운드에서 소멸되므로 0이 출력됩니다.

입력출력
10
01

2. AND Gate (두 입력이 모두 1일 때만 1을 출력하는 부품)

두 개의 트랜지스터가 직렬로 연결되어 있습니다. 둘 중 하나라도 0이면 전류가 차단되어 0이 출력되고, 둘 다 1일 때만 전류가 통과하여 1이 출력됩니다.

입력 A입력 B출력
000
100
010
111

3. OR Gate (두 입력 중 하나라도 1이면 1을 출력하는 부품)

두 개의 트랜지스터가 병렬로 연결되어 있습니다. 둘 중 하나라도 1이면 전류가 흘러 1이 출력됩니다.

입력 A입력 B출력
000
101
011
111

4. XOR Gate (두 입력이 서로 다를 때 1을 출력하는 부품)

왼쪽이 입력, 오른쪽이 출력입니다. A와 B 두 개의 입력이 있으며, 둘 다 0이면 전류가 흐르지 않아 0이 출력됩니다. 둘 다 1이면, 내부 NOT Gate에 의해 상쇄되어 0이 출력됩니다. A와 B가 서로 다른 값일 때만 1이 출력됩니다.

CPU 명령어 처리 과정#

논리 연산의 기본 원리를 알았으니, CPU가 실제로 명령어를 어떻게 처리하는지 예시를 통해 알아보겠습니다.

참고 자료: CPU 명령어 처리 과정 (YouTube)

  • 위 그림은 특정 프로그램을 실행하여 100번, 101번, 102번 주소에 명령어가 메모리에 올라온 상태입니다.
  • 10번과 11번 주소에는 각각 3과 4라는 데이터가 할당되어 있습니다.
  • 아래 과정은 모두 CPU의 제어 장치(Control Unit)가 총괄합니다.

I. LOAD 10 처리#

  1. 다음 명령어의 주소를 가리키는 프로그램 카운터에 100이 저장됩니다.
  2. 메모리 주소 레지스터에 100이 옮겨집니다.
  3. 100번 주소에서 LOAD 10을 가져와 메모리 데이터 레지스터에 저장합니다.
  4. LOAD 10은 명령어이므로 명령어 레지스터로 이동합니다.
  5. 프로그램 카운터가 다음 주소인 101로 증가합니다. (프로그램 카운터는 항상 다음에 읽어올 명령어의 주소를 가지고 있어야 하기 때문입니다.)
  6. 명령어 레지스터의 명령어가 제어 장치로 전달되어 Decode(해독)됩니다.
  7. CPU가 LOAD 10을 수행하기 위해 메모리 주소 레지스터에 10을 저장합니다.
  8. 10번 주소의 데이터인 3이 메모리 데이터 레지스터에 저장됩니다.
  9. CPU는 3이라는 데이터가 연산에 사용될 것임을 알고, 어큐뮬레이터로 이동시킵니다. 이로써 LOAD 10 명령어의 처리가 완료됩니다.

II. ADD 11 처리#

  1. 프로그램 카운터에 있는 101이 메모리 주소 레지스터로 이동합니다.
  2. 101번 주소에서 ADD 11을 메모리 데이터 레지스터로 가져옵니다.
  3. 명령어이므로 명령어 레지스터로 이동합니다.
  4. 프로그램 카운터가 102로 증가합니다.
  5. ADD 11이 제어 장치에서 Decode됩니다.
  6. CPU는 ADD 명령어를 처리하기 위해, 어큐뮬레이터에 있는 3을 ALU로 이동시킵니다.
  7. 메모리 주소 레지스터에 11이 저장됩니다.
  8. 11번 주소의 데이터인 4가 메모리 데이터 레지스터에 저장됩니다.
  9. 4가 연산에 사용될 데이터이므로 어큐뮬레이터로 이동합니다.
  10. ALU에서 이미 있던 3과 더해져 7이 됩니다.
  11. 결과인 7이 어큐뮬레이터로 이동합니다. 이로써 ADD 11 명령어의 처리가 완료됩니다.

III. STORE 12 처리#

  1. 프로그램 카운터의 102가 메모리 주소 레지스터로 이동합니다.
  2. 102번 주소에서 STORE 12를 메모리 데이터 레지스터로 가져옵니다.
  3. 명령어이므로 명령어 레지스터로 이동합니다.
  4. 프로그램 카운터가 103으로 증가합니다. 그러나 103에는 명령어가 없으므로, 이 프로그램이 종료될 예정임을 의미합니다.
  5. STORE 12가 제어 장치에서 Decode됩니다. 12번 주소에 결과 값을 저장하라는 의미입니다.
  6. 메모리 주소 레지스터에 12가 저장됩니다.
  7. 이번에는 메모리에서 데이터를 가져오는 것이 아니라, 어큐뮬레이터에 있던 7을 메모리 데이터 레지스터로 이동시킵니다.
  8. 12번 주소에 7이 저장됩니다. 이로써 STORE 12 명령어의 처리가 완료됩니다.

위 예시는 3과 4를 더하여 7이라는 결과를 저장하는 단순한 과정인데도 매우 복잡하다는 것을 알 수 있습니다. 실제 프로그램은 고급 언어로 작성한 로직 자체도 복잡한 경우가 많은데, 이를 수행하는 CPU가 얼마나 많은 일을 처리하는지 체감할 수 있습니다. 또한 동일한 출력을 내는 코드라도 왜 더 효율적인 방식으로 구현해야 하는지도 이해할 수 있게 됩니다.

이렇게 복잡한 과정을, 인간은 고수준 프로그래밍 언어를 통해 간단하게 지시할 수 있습니다.

// Dart 기준
int A = 3;
int B = 4;
int C = A + B;
// print(C); → 출력 값: 7

# Python 기준
A = 3
B = 4
C = A + B
# print(C) → 출력 값: 7

// Java 기준
int A = 3;
int B = 4;
int C = A + B;
// System.out.println(C); → 출력 값: 7

// JavaScript 기준
var A = 3;
var B = 4;
var C = A + B;
// console.log(C); → 출력 값: 7

4. 비트와 2진수에 대하여#

프로그래머가 하는 일은 본질적으로 데이터와 정보를 다루는 것입니다. 정보의 기본 단위인 비트와 2진수에 대해 알아보겠습니다.

데이터와 정보#

  • 데이터: 현실로부터 측정, 관측을 통해 얻은 사실 또는 값들
  • 정보: 데이터를 유용한 형태로 변환하는 처리 과정을 거쳐 의미를 부여한 것

예를 들어, “소득"과 “게임 구매량"이라는 데이터를 수집하고 가공하여 시각화하면 다음과 같은 정보를 얻을 수 있습니다.

이 산점도 그래프를 통해 “소득이 증가함에 따라 게임 구매량이 증가한다"는 유용한 정보를 도출할 수 있습니다.

프로그래머는 이러한 데이터(정보)를 디지털 데이터, 디지털 정보라고 부릅니다. 기계가 이해하는 언어로 변환된 데이터를 다루기 때문에 붙여진 이름이며, 본질은 동일합니다.

비트(Binary Digit)#

비트(bit): 정보이론의 아버지인 Claude Elwood Shannon에 의해 공식화된 이름으로, 하나의 비트는 0 또는 1의 값을 가질 수 있으며, 각각은 참/거짓 또는 서로 배타적인 상태를 나타냅니다.

8개의 비트가 모여 1개의 바이트(byte)를 형성합니다. 바이트는 메모리 주소의 기본 단위이기도 합니다.

또한 바이트 2개(16비트)가 모여 하나의 워드(Word)를 형성하며, 이는 CPU가 데이터를 다루는 기본 단위, 즉 레지스터의 크기를 의미합니다. 현대 컴퓨터는 대부분 64비트 CPU를 사용하므로, 워드 크기도 64비트입니다. CPU 또는 시스템에 따라 워드의 크기는 달라집니다.

10진수를 2진수로 표현하기#

먼저 256이 10진수로 어떻게 표현되는지 살펴보겠습니다.

256 = 2 x 10^2 + 5 x 10^1 + 6 x 10^0

모든 10진수는 밑(Base)이 10인 거듭제곱 형태로 표현할 수 있습니다. 같은 원리로 11이라는 10진수를 2진수로 표현하면 다음과 같습니다.

11 = 1 x 2^3 + 0 x 2^2 + 1 x 2^1 + 1 x 2^0

148(10진수) = 10010100(2진수)임을 알 수 있습니다.

2진수의 덧셈#

10 + 1은 11이 됩니다. 11 + 1은 십진법이 아닌 이진법이므로 올림이 발생하여 100이 됩니다. 8비트의 덧셈도 자릿수만 늘어날 뿐 원리는 동일합니다.

부호가 있는 정수 (Signed Integer)#

부호가 있는 비트에서 첫 번째 비트가 1이면 음수, 0이면 양수를 나타냅니다. 8비트를 기준으로 설명하겠습니다.

이를 이해하려면 2의 보수 방법을 알아야 합니다. 방법은 다음과 같습니다.

  1. 비트의 각 자리를 반전시킵니다 (1은 0으로, 0은 1로).
  2. 결과에 1을 더합니다.

예를 들어, -5를 8비트로 표현하는 과정은 다음과 같습니다.

  • 5를 2진수로 표현: 0000 0101
  • 비트 반전: 1111 1010
  • 1을 더함: 1111 1011

1111 1011에 0000 0101(5)을 더하면 0이 되므로, 1111 1011이 -5임을 확인할 수 있습니다.

8비트 기준 정수의 범위는 다음과 같습니다.
